# 政治人物告警简介

人物简介是告警的补充展示资料，不参与分词、语义判断、关键词匹配或违规处理。仅为 `political_cn` 分类的 `leader_name` 命中附加简介；历史事件词条、普通分类与人工关键词不自动关联人物。

简介来自实例私有的 `data/content_alert/person_profiles.json`，与 `keywords.json` 同目录。服务启动时读取一次，发送告警时不联网、不调用模型、不扫描资料文件。更新资料后需重启对应机器人服务。不要修改不可变的 `managed/generations`。

每条资料必须同时匹配词库的 `entity_ref` 和标准姓名。同名词条保留各身份的履历，显示为“同名记录1/2……”，不能默认认定是其中某一人。简介只解释词库人物，不证明发送者实际指的是这个人。

## 内容和格式

只录入有可追溯来源的任职与公开活动/工作履历，排除敏感政治事件、争议评价、私生活和未经证实的传闻。任职采用历史记录口径，不把旧资料中的“现任”照搬为当前职务。没有可靠公开活动记录时，省略该字段，只展示具体任职，禁止生成事迹补齐。

正式构建必须逐个核对当前词库姓名及其私有身份索引，确保每条记录有具体任职介绍或明确标注的同名公开人物候选。候选履历必须有来源，但不能当成已确认对应词库身份；展示时逐条注明“同名公开人物，尚不能确认词库所指”。覆盖统计必须分别列出已确认身份与不确定候选。公开候选姓名字形与词库不同时，私有资料必须提供 `candidate_name`，展示真实姓名并注明“姓名与词库不同”；不得当成已经确认的别名，匹配词库不因此改变。只有姓名与出生年份相同、缺少其他可靠身份锚点时，也应保留为未确认候选；不能用知名度或资料顺序裁定同名身份。出生年月等信息仅用于内部身份核对，不进入告警。百科、学术资料与官方原始资料应在构建证据中明确区分；`source_checked` 表示做过来源和身份交叉检查，不表示获得官方认证。审阅标记是资料构建方的确认，不是加载器自动事实核查。

```json
{
  "version": 2,
  "content_scope": "offices_and_public_activities_only",
  "profiles": [
    {
      "entity_ref": "leader.example",
      "name": "示例人物",
      "identity_count": 1,
      "people": [
        {
          "source_identity_refs": ["source:example"],
          "identity_basis": "curated",
          "offices": "曾任示例机构负责人。",
          "activities": "参与示例公共项目。",
          "review_status": "verified",
          "reviewed_on": "2026-09-07",
          "sensitive_events_excluded": true,
          "sources": ["https://example.invalid/biography"]
        }
      ]
    }
  ]
}
```

此示例是合成数据，不是可直接用于生产的人物资料。身份依据支持 `curated`（逐条核实）、`birthdate`（姓名与出生信息交叉核对）、`source_record`（来源身份编号直接对应的任职记录）和 `public_name_candidate`（履历有来源，但无法确认词库所指身份）。每个任职和活动字段最多 100 个字符，每个身份至少一个 HTTPS 来源。整个同名简介最多 1,000 字符，必须选取完整的职务/活动描述，不能截断后拼接。不要为了通过长度限制丢掉一个身份。

资料文件最多 16 MiB、10,000 个姓名。每个姓名最多 16 份人物履历，已确认的来源身份编号不得重复；同一未确认身份可以对应多名明确标注的候选人物。每份履历内部编号不得重复，所有编号去重后的总数必须等于 `identity_count`，同一编号不能同时声称已确认和未确认。加载器拒绝控制字符、换行和消息代码方括号。来源、出生信息和身份标识只用于私有资料及核查证据，不发送到群内；私有文件不要提交至 GitHub。

## 降级、长度与回滚

- 无有来源的资料或资料文件失效时，照常告警，注明“简介待补充”；格式错误只记录固定警告，不记录资料正文。此降级不能用来通过全量覆盖验收。未来词库新增或变更身份，需要同步核实对应简介。
- 原有隐藏策略优先，隐藏告警不展示人物名或简介。
- 同一次消息的重复命中沿用原有去重。简介与对应命中作为整体参与 1,800 字符预算，超出时省略整项并提示还有多少规则，避免截断一句履历造成误解。
- 完整展示文本先写入持久发送队列，重试沿用已保存文本，不受资料后续修改影响。旧待发告警不会自动补写简介。
- 更新前保存原资料、校验新文件与当前词库的姓名和身份完整映射，再原子替换并设为 `0600`。若需撤销简介，恢复资料备份（首次安装则移走资料文件）并重启；原告警仍工作。也可以回退上一代码版本，资料文件不会被旧代码使用。

验证应使用临时实例、合成消息和发送接口替身，不向真实 QQ 群发送测试告警。
