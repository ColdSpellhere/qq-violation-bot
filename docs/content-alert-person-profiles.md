# 政治人物告警简介

人物简介是告警的补充展示资料，不参与分词、语义判断、关键词匹配或违规处理。仅为 `political_cn` 分类的 `leader_name` 命中附加简介；历史事件词条、普通分类与人工关键词不自动关联人物。

简介来自实例私有的 `data/content_alert/person_profiles.json`，与 `keywords.json` 同目录。服务启动时读取一次，发送告警时不联网、不调用模型、不扫描资料文件。更新资料后需重启对应机器人服务。不要修改不可变的 `managed/generations`。

每条资料必须同时匹配词库的 `entity_ref` 和标准姓名。多个同名身份合并的词条不能按其中一人的履历填写。简介仅解释“词库中的人物”，不证明发送者实际指的是这个人。

## 内容和格式

只录入经过来源核实的任职与公开活动/工作履历，排除敏感政治事件、争议评价、私生活和未经证实的传闻。任职采用“曾任”或“任职经历包括”，不把旧资料中的“现任”照搬为当前职务。来源正文不直接复制到告警。审阅标记是操作人员对内容的确认，不是自动事实核查。

```json
{
  "version": 1,
  "content_scope": "offices_and_public_activities_only",
  "profiles": [
    {
      "entity_ref": "leader.example",
      "name": "示例人物",
      "offices": "曾任示例机构负责人。",
      "activities": "参与示例公共项目。",
      "identity_count": 1,
      "review_status": "verified",
      "reviewed_on": "2026-09-07",
      "sensitive_events_excluded": true,
      "sources": ["https://example.invalid/biography"]
    }
  ]
}
```

此示例是合成数据，不是可直接用于生产的人物资料。每个任职和活动字段最多 100 个字符，至少一个 HTTPS 来源，来源和身份标识只保留在私有资料中，不发送到群内。资料文件最多 4 MiB、10,000 条，拒绝控制字符、换行和消息代码方括号。私有文件不要提交至 GitHub。

## 降级、长度与回滚

- 无资料、身份不明确或资料文件失效时，照常告警，注明“简介待补充”；格式错误只记录固定警告，不记录资料正文。
- 原有隐藏策略优先，隐藏告警不展示人物名或简介。
- 同一次消息的重复命中沿用原有去重。简介与对应命中作为整体参与 1,800 字符预算，超出时省略整项并提示还有多少规则，避免截断一句履历造成误解。
- 完整展示文本先写入持久发送队列，重试沿用已保存文本，不受资料后续修改影响。旧待发告警不会自动补写简介。
- 更新前保存原资料、校验新文件与当前词库身份映射，再原子替换并设为 `0600`。若需撤销简介，恢复资料备份（首次安装则移走资料文件）并重启；原告警仍工作。也可以回退上一代码版本，资料文件不会被旧代码使用。

验证应使用临时实例、合成消息和发送接口替身，不向真实 QQ 群发送测试告警。
