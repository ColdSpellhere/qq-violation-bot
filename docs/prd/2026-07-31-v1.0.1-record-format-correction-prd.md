## 2. 背景

管理员提交新增违规记录时，如果缺少 QQ号、分区、时间、违规行为或处理措施，机器人目前只返回简短提示，例如：

```text
缺少必要信息：时间。
```

这类提示只能说明问题，不能帮助用户快速改正。用户需要重新回忆完整格式，容易重复遗漏字段，也会增加群内来回沟通次数。

当前帮助信息虽然包含记录示例，但没有把用户已经提供的内容重组成一条可直接复制的纠正语句，也没有明确解释哪些字段必须填写、哪些字段有条件必填、哪些字段由机器人自动填充。

## 3. 产品目标

当新增违规记录因字段缺失、字段不明确或目标成员无法唯一识别而不能继续时，机器人应：

1. 一次性列出当前能够确定的全部缺失项。
2. 保留已经可靠识别的原始内容。
3. 按统一顺序重组为一条标准单行记录。
4. 在缺失位置插入清晰的尖括号占位符。
5. 让用户只替换尖括号内容即可重新发送。
6. 解释条件必填、可选和自动填充字段。

## 4. 核心红线

本版本只增强“新增违规记录失败时的纠正回复”，不得借此改变现有业务行为。

- 不修改现有 NLP 意图分类和字段抽取规则。
- 不改变正常新增记录、预览、确认、取消和入库流程。
- 不改变成员查询、分区查询、导出、质询、最后警告或状态操作。
- 不改变现有昵称模糊搜索算法、阈值或候选返回规则。
- 不改变历史查询结果的文本结构、排序、证据图片展示或数据库查询逻辑。
- 不把 QQ号改成所有场景强制必填。
- 格式纠正回复不得创建待确认操作，不得新增违规记录，不得写入业务数据。
- 不扩大机器人处理群范围，不改变目标群之外消息直接忽略的边界。

## 5. 适用范围

### 5.1 触发范围

仅当消息已经进入现有的“新增违规记录”流程，并被现有校验判定为以下情况时触发：

- 缺少一个或多个必要字段；
- 昵称无法唯一确定成员；
- 目标成员未找到，且缺少创建成员所需信息；
- 某字段解析结果不够确定，需要用户重新确认；
- 处理人被明确表示为其他人，但无法确定其身份。

### 5.2 不触发范围

- 新增记录信息完整且能够正常进入预览；
- 查询、导出、确认、取消及其他非新增记录意图；
- 框架错误、AI 接口异常、数据库异常或网络异常；
- 目标群之外的任何消息。

## 6. 标准纠正格式

标准单行模板顺序为：

```text
<分区> <成员昵称>（<QQ号>） <日期> <时间> <违规行为>，<处理措施>，<处理人>
```

实际回复时：

- 已可靠识别的内容直接填入模板；
- 缺失或无法确定的内容使用 `<字段说明>`；
- 不需要用户填写的自动字段不放进主模板；
- 日期为当天时可以省略，主模板不得为了形式完整而强制补日期；
- 处理人未填写时默认等于记录人，因此不应无条件插入处理人占位符。

## 7. 字段规则

| 字段 | 规则 | 缺失时处理 |
|---|---|---|
| 分区 | 必填，只允许蜂巢、蜂窝、蜂箱 | 插入 `<分区：蜂巢/蜂窝/蜂箱>` |
| 成员昵称 | 已有成员可通过 QQ号识别；新成员需要昵称 | 仅在现有流程确实需要昵称时插入 `<成员昵称>` |
| QQ号 | 条件必填。昵称唯一命中时可不提供 | 昵称多人匹配、未找到或需要创建成员时插入 `<QQ号>` |
| 日期 | 当天记录可省略；非当天建议写月/日或年/月/日 | 不作为当天记录的独立必填项 |
| 时间 | 必填，使用 24 小时制，如 03:30、15:30 | 插入 `<时间，24小时制，如03:30或15:30>` |
| 引用消息时间 | 回复或引用原消息且用户未另写时间时，沿用现有逻辑自动获取 | 已成功获取时不插入时间占位符 |
| 违规行为 | 必填 | 插入 `<违规行为>` |
| 处理措施 | 必填 | 插入 `<处理措施>` |
| 处理人 | 可选，未填写时默认等于记录人 | 只有明确表示由其他人处理但身份不清时才插入 `<处理人QQ号或昵称>` |
| 记录人 | 自动取当前消息发送者 | 不进入主模板，不要求用户填写 |
| 备注 | 可选，未填写时默认“无” | 不进入主模板，不插入占位符 |
| 证据图片 | v1.0.1 保持当前提醒模式 | 不阻止纠正或现有新增流程 |

## 8. 回复结构

纠正回复固定由三部分组成：

1. 缺失项摘要；
2. 可复制的标准单行记录；
3. 与本次缺失项有关的简短字段说明和自动填充说明。

建议格式：

```text
格式缺少：QQ号、时间

请替换尖括号内容后重新发送：
蜂巢 小明（<QQ号>） <时间，24小时制，如03:30或15:30> 刷屏，禁言，企鹅处理

说明：
- QQ号：昵称无法唯一确定时必填
- 记录人：自动取当前发送者
- 未写处理人时：默认等于记录人
- 备注：未写时默认为“无”
```

回复应保持简洁，不重复输出与本次问题无关的完整帮助菜单。

## 9. 典型场景

### 9.1 缺少 QQ号和时间

用户输入：

```text
小明 蜂巢 刷屏 禁言 企鹅处理
```

前提：昵称“小明”无法唯一确定成员。

期望纠正行：

```text
蜂巢 小明（<QQ号>） <时间，24小时制，如03:30或15:30> 刷屏，禁言，企鹅处理
```

### 9.2 昵称能够唯一命中

用户输入：

```text
蜂巢 小明 15:30 刷屏 禁言
```

前提：昵称“小明”按照现有逻辑能够唯一命中成员。

期望行为：继续进入现有预览流程，不因未写 QQ号而显示纠正模板。

### 9.3 缺少分区和处理措施

用户输入：

```text
小明（123456）15:30 刷屏
```

期望纠正行：

```text
<分区：蜂巢/蜂窝/蜂箱> 小明（123456）15:30 刷屏，<处理措施>
```

### 9.4 引用消息自动取时间

用户引用一条群消息并输入：

```text
蜂巢 小明（123456）刷屏，禁言
```

前提：现有引用消息逻辑已成功取得原消息时间。

期望行为：不插入 `<时间>`，继续使用引用消息时间进入现有预览流程。

### 9.5 明确由其他人处理但身份不清

用户输入：

```text
蜂巢 小明（123456）15:30 刷屏，禁言，由管理员处理
```

期望纠正行：

```text
蜂巢 小明（123456）15:30 刷屏，禁言，<处理人QQ号或昵称>
```

## 10. 交互与数据流程

```text
目标群消息
  -> 现有 NLP 解析
  -> 现有新增记录校验
  -> 信息完整：保持现有预览和确认流程
  -> 信息缺失或不明确：生成标准纠正模板并直接回复
  -> 用户替换占位符后重新发送
  -> 重新进入现有解析和校验流程
```

纠正模板生成器只消费现有解析和校验结果，不负责重新识别意图、搜索成员或写入数据库。

## 11. 验收标准

### 11.1 功能验收

- 单个字段缺失时，只插入对应占位符。
- 多个字段缺失时，一次性列出并插入全部占位符。
- 已可靠识别的分区、昵称、QQ号、时间、违规行为、处理措施和处理人保持原值。
- 输出为统一标准单行模板，不依赖用户原句字段顺序。
- 时间说明明确采用 24 小时制，并包含 03:30 和 15:30 两个示例。
- 昵称唯一命中时，不新增 QQ号强制要求。
- 昵称多人匹配或未找到时，显示 `<QQ号>`。
- 引用消息时间已成功取得时，不显示时间占位符。
- 记录人、默认处理人和默认备注规则说明正确。

### 11.2 回归验收

- 现有查询契约测试保持通过，查询文本和排序不变。
- 现有昵称模糊搜索算法及候选结果不变。
- 正常新增记录的预览文本、确认方式和入库结果不变。
- 旧记录查询及证据图片展示不变。
- 格式纠正回复不产生待确认数据或违规记录。
- 目标群之外消息仍然不进入自定义处理。

### 11.3 测试覆盖

- 缺分区；
- 缺目标成员；
- QQ号条件必填；
- 昵称唯一命中；
- 昵称多人匹配；
- 缺时间；
- 引用消息自动取时间；
- 缺违规行为；
- 缺处理措施；
- 其他处理人身份不清；
- 多字段同时缺失；
- 正常新增流程回归；
- 查询流程回归。

## 14. 后续事项

昵称模糊搜索优化已登记为 `v1.0.4-beta`。现有匿名聚合数据表明，部分完全一致的昵称仍会因多个低分候选而返回歧义；该问题需要单独设计匹配优先级、分数差阈值、候选展示和回归测试，不在本 PRD 中处理。

## 15. 风险与回滚原则

- 最大风险是纠正模板误判字段，导致用户复制后仍无法通过校验。
- 实现时必须复用现有解析结果，不新增第二套 NLP 或字符串分词逻辑。
- 必须保留现有简短错误提示作为异常降级路径，模板生成失败时仍能正常回复。
- 上线后如出现异常，只回滚格式纠正调用，不回滚数据库或历史记录。
- 本功能不包含数据库结构变更，因此回滚不需要数据迁移。
