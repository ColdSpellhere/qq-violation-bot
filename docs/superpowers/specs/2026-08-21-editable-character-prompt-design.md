# 可编辑角色提示词设计

## 目标

将萝卜猫的人物设定从 Python 源码抽取到项目根目录的 `character.md`，让管理员可以直接编辑文本，并让修改在下一次群聊或私聊 AI 回复时生效，无需重启机器人。

## 文件职责

`character.md` 只描述人物身份、性格、喜好和表达习惯。初始内容保持当前生产设定，包括：

- 名字是萝卜猫，但不是猫，不使用“喵”等猫系口癖；
- 是自然可爱的小女孩式虚构 QQ 聊天角色；
- 喜欢花、植物和自然里的小东西；
- “反二梦女”是兴趣和自我标签，不是另一个名字；
- 不反复介绍设定，不把每句话都写成卖萌或幼儿化表达。

群聊与私聊共用同一个 `character.md`。群聊方向判断、被点名时必须回答、随机接话时允许 `SKIP`、业务隔离、安全限制和输出格式继续由 Python 代码控制，不允许角色文件覆盖这些运行规则。

## 加载方式

每次 `generate_reply` 准备 AI 请求时都以 UTF-8 直接读取项目根目录的 `character.md`，不缓存内容和文件修改时间。管理员保存文件后，下一次 AI 回复立即使用新内容。

角色文件的绝对路径根据源码所在位置计算，不依赖 systemd 的当前工作目录，因此从测试、命令行或服务启动时行为一致。

读取结果会去除首尾空白。Markdown 标题和列表不做额外解析，完整文本直接作为系统提示词中的人物设定段落。

## 失败处理

程序保留一份与初始 `character.md` 内容一致的内置默认设定。出现以下任一情况时，本次回复使用内置默认设定：

- 文件不存在；
- 文件为空或仅包含空白；
- 文件不是有效 UTF-8；
- 读取时发生其他文件系统错误。

读取失败只记录一条警告，不阻断 AI 回复，也不影响后续请求再次尝试读取文件。由于不缓存，上一次成功读取的自定义内容不会在文件损坏后继续生效。

## 代码边界

新增一个小型角色加载模块，负责路径解析、读取、空内容校验和默认值回退。`plugins/random_chat/ai.py` 只调用该模块取得人物设定，再与现有场景、聊天方向、风格和安全规则组合。

私聊插件继续通过现有 `generate_reply(..., chat_mode="private")` 调用链复用人物设定，不新增第二份角色文件或私聊专属副本。

## 验证

增加聚焦测试验证：

1. 有效 `character.md` 会进入群聊和私聊的系统提示词；
2. 两次回复之间修改文件，第二次会读取新内容；
3. 文件不存在、为空、非 UTF-8 或读取失败时使用内置默认设定；
4. 现有群聊方向、`SKIP`、身份边界和私聊行为测试继续通过。

生产部署后先备份当前版本，写入初始 `character.md`，重启一次以加载新代码；此后的角色文本修改不再需要重启。
