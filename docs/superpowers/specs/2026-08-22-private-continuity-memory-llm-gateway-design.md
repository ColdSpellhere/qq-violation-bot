# 私聊连续性、关系状态、记忆治理与统一模型调用设计

## 1. 文档状态

- 日期：2026-08-22
- 状态：设计已确认，尚未进入实现
- 目标版本：后续实施计划确定
- 基线提交：`c7c010ba6f6ab8e857415e5d623a763628e5e5f0`
- 适用仓库：`ColdSpellhere/qq-violation-bot`

本文档描述萝卜猫聊天体系下一阶段的增量设计。它不重构现有违规业务系统，不改变违规记录、禁言、减数、状态锁定或管理员权限规则。

## 2. 背景与现状

当前项目已经具备：

- NoneBot2、OneBot V11 与 NapCat 接入；
- 严格业务意图解析、字段校验、二次确认和审计；
- 业务路由与聊天路由隔离；
- 随机群聊、明确 @ 必回、表情包和可热更新人设；
- 包含发送者、QQ、昵称、@、引用和图片描述的群聊上下文；
- 群成员永久事实账本和滚动摘要；
- 白名单私聊及进程内最近对话；
- 群聊图片理解和原图生命周期；
- QQ 内运行时开关；
- 业务 outbox、调度、备份、迁移和运维监控。

诊断确认的主要缺口是：

1. 私聊最近对话只保存在进程内，重启后丢失；
2. 事实记忆和摘要之外没有独立、可并发治理的关系状态；
3. 缺少超级管理员可使用的统一记忆治理命令；
4. 不同插件重复建立模型连接、解析错误和管理重试；
5. 聊天提示的拼装逻辑集中在调用方内部，长度预算和信任边界不够集中。

## 3. 目标与非目标

### 3.1 目标

- 为白名单私聊用户提供跨重启的分层记忆；
- 为群聊成员和私聊用户提供独立关系状态；
- 允许超级管理员查看、添加、修正、删除和清理记忆，且全过程可审计；
- 建立统一、可测试的 LLM Gateway，并按风险逐步迁移现有调用；
- 建立可测试的 Prompt Builder，集中处理上下文预算和信任边界；
- 所有新增能力都能通过运行时开关独立关闭；
- 关闭新增能力后保持现有机器人行为不变。

### 3.2 非目标

- 不回溯分析历史群聊、历史私聊或旧图片；
- 不改动已有违规业务规则和业务数据库语义；
- 不让聊天模型直接执行任何群管理操作；
- 第一阶段不实现联网搜索、人设历史或费用查询界面；
- 不建立第二套白名单、第二个重复的记忆数据库或重复状态源；
- 不把推测、情绪猜测或模型生成内容自动视为确定事实。

## 4. 已选方案

采用增量共享核心方案：

- 继续使用现有 `chat_archive.db` 保存聊天与记忆相关数据；
- 复用 `member_memory` 的事实账本、摘要水位和乐观并发思路；
- 复用 feature control 的原子运行时配置与现有白名单；
- 复用 scheduler/outbox 的任务持久化、认领、租约和恢复思想；
- 保留现有群成员记忆表和历史数据；
- 只从功能启用后的新消息开始建立私聊记忆和关系状态。

该方案比独立新数据库或一次性重构更容易回滚，也能避免聊天数据出现多个互相矛盾的来源。

## 5. 隐私、保留、清理与导出

### 5.1 数据范围

只有当前私聊白名单内的用户才允许建立持久化私聊记忆。不同用户以 `user_id` 为硬隔离键，不允许跨用户读取、摘要、关系更新或提示注入。

私聊数据与以下内容保持语义隔离：

- 群聊原文；
- 群成员事实和群成员摘要；
- 违规记录、证据、禁言、减数、状态锁定；
- 管理员和功能权限。

### 5.2 原文保留策略

每名白名单用户的私聊原文同时受两个上限控制：

- 最多 500 条；
- 最长 30 天。

任一上限达到即清理最旧原文。摘要、经确认的长期事实和关系状态不会随原文自动删除，必须通过治理操作处理。

原文清理后可保留用于追踪的一小组非正文元数据：消息标识、内容哈希、时间、水位，以及确有必要的短来源摘录。短摘录必须受长度限制，不能成为规避原文期限的副本。

### 5.3 备份与导出

- 迁移前备份 `chat_archive.db`；
- 含私聊原文的聊天数据库备份同样执行 30 天保留策略；
- 导出仅允许超级管理员触发；
- 原文导出必须明确预览并二次确认；
- 导出文件权限为 `0600`，目录权限为 `0700`；
- 导出目录加入 Git 忽略，并在 24 小时后自动清理；
- 不在日志、审计摘要或模型调用统计中记录完整私聊正文。

### 5.4 安全删除

清理任务删除原文后执行适当的 SQLite checkpoint 和安全删除流程。实现计划需要验证所使用 SQLite 版本对 `secure_delete` 的实际行为，并避免在在线高峰执行昂贵的整库压缩。

## 6. 数据模型

所有新表位于 `chat_archive.db`。字段名可在实施阶段按现有代码风格微调，但语义和约束不得弱化。

### 6.1 私聊原文 `private_chat_messages`

建议字段：

- `id`：内部递增水位；
- `user_id`：私聊用户；
- `message_id`：OneBot 消息标识；
- `direction`：`user` 或 `assistant`；
- `text`：规范化后的文本；
- `content_hash`：正文哈希；
- `event_time`：消息事件时间；
- `created_at`：持久化时间；
- `expires_at`：原文到期时间；
- `purged_at`：清理时间；
- `source_kind`：文本、图片描述或混合消息等来源类型。

约束：

- 用户消息在调用模型前提交；
- 机器人回复仅在 QQ 发送成功后提交；
- 以稳定事件键实现幂等，避免重连或重放产生重复记录；
- 查询必须同时带 `user_id`，不能仅凭全局消息编号读取。

### 6.2 私聊滚动摘要 `private_conversation_summaries`

建议字段：

- `user_id`；
- `summary_text`；
- `source_start_id`；
- `source_end_id`；
- `summarized_through_id`；
- `version`；
- `created_at`；
- `updated_at`。

摘要只能覆盖连续、已提交的消息区间。提交时使用水位和版本条件，旧任务不能覆盖新摘要。

### 6.3 私聊长期事实 `private_memory_facts`

建议字段：

- `id`；
- `user_id`；
- `fact_text`；
- `source_message_id`；
- `source_quote`；
- `confidence_level`：自动抽取或人工确认；
- `status`：生效、已取代、已删除；
- `supersedes_id`；
- `version`；
- `created_at`；
- `updated_at`；
- `deleted_at`。

人工确认的事实具有高于 AI 自动抽取的可信等级。更正通过新增版本并标记旧项被取代实现，不直接覆盖历史。

### 6.4 关系状态 `relationship_states`

建议字段：

- `conversation_kind`：`group` 或 `private`；
- `group_id`：群聊作用域，私聊时为空；
- `user_id`；
- `persona_id`；
- `state_text`；
- `open_topics`：结构化列表或受控 JSON；
- `preferred_address`；
- `communication_style`；
- `source_message_id`；
- `source_watermark`；
- `version`；
- `created_at`；
- `updated_at`。

唯一作用域为：

- 群聊：`group_id + user_id + persona_id`；
- 私聊：`user_id + persona_id`。

注入模型前限制：

- `state_text` 最多约 600 字符；
- 未完话题最多 5 条；
- 每条话题最多约 80 字符。

关系状态只能改变聊天表达，任何业务模块不得读取此表作为决策输入。

### 6.5 持久化任务 `memory_jobs`

用于私聊摘要、长期事实抽取和关系更新。建议字段包括：

- 任务类型、会话作用域和输入水位；
- 状态、尝试次数、下次执行时间；
- 认领者、租约截止时间；
- 期望状态版本；
- 错误分类和脱敏错误摘要；
- 创建、更新时间。

任务表只保存可恢复的引用和水位，不保存完整 Prompt、API Key 或响应正文。

### 6.6 治理审计与待确认操作

新增记忆专用审计和待确认表，不复用业务操作表：

- `memory_governance_audit`：操作人、目标作用域、操作类型、前后内容或哈希、原因、时间、结果；
- `memory_pending_operations`：一次性确认码、操作人、目标、预览、过期时间和消费状态。

删除事实使用软删除；清理私聊原文可以物理删除正文，但审计记录必须保留，且不得写入完整被删正文。

## 7. 关系状态更新规则

关系状态描述熟悉程度、最近互动氛围、重要互动、未完话题、称呼和交流方式。它不是人物事实表，也不是心理诊断。

更新流程：

1. 读取当前状态、版本和消息水位；
2. 基于新消息生成候选状态；
3. 验证候选结构、长度和不确定性表达；
4. 仅当数据库版本和输入水位仍匹配时提交；
5. 如发生冲突，旧任务放弃或按新水位重新排队；
6. 模型失败、解析失败或提交失败时保留旧状态。

模型推测必须使用不确定表达，不能写成确定事实。稳定事实应进入事实账本，关系状态只保存聊天所需的近期关系信息。

## 8. 统一记忆治理命令

### 8.1 命令形式

采用统一 `/记忆` 命名空间：

查看：

- `/记忆 @某人`
- `/记忆 <QQ号>`
- `/记忆 关系 @某人`
- `/记忆 关系 <QQ号>`
- `/记忆 状态`

修改：

- `/记忆 添加 @某人 <内容>`
- `/记忆 添加 <QQ号> <内容>`
- `/记忆 修改 <记忆编号> <内容>`
- `/记忆 删除 <记忆编号>`
- `/记忆 关系 @某人 <新状态>`
- `/记忆 关系 <QQ号> <新状态>`
- `/记忆 清空 <QQ号>`

确认：

- `/记忆 确认 <操作码> <原因>`
- `/记忆 取消 <操作码>`

帮助：

- `/记忆`
- `/记忆 帮助`

群聊事实编号使用 `G-<id>`，私聊事实编号使用 `P-<id>`，避免作用域混淆。

### 8.2 鉴权和隐私

- 所有命令仅允许现有超级管理员执行；
- 在进入聊天模型前精确识别并阻断命令前缀；
- 群成员目标必须使用真实 @ 消息段；
- 私聊 QQ 号只接受 ASCII 数字；
- 私聊人工事实只允许写入当前白名单用户；
- 含记忆正文的查询结果私聊发送给超级管理员；
- 私聊发送失败时不得回退到群内展示私人内容。

### 8.3 危险操作

所有修改、删除、关系覆盖和清理操作都执行：

1. 生成清晰预览；
2. 返回 10 分钟有效的一次性确认码；
3. 确认码绑定操作人和完整操作内容；
4. 确认时提供原因；
5. 数据变更与审计写入同一事务；
6. 事务失败返回失败，不得回复成功。

`/记忆 清空 <QQ号>` 清理：

- 私聊原文正文；
- 私聊滚动摘要；
- 未完话题；
- 对应待执行摘要任务。

它不清理：

- 长期事实；
- 关系状态；
- 审计记录。

这些内容必须通过各自可审计的删除或修改命令处理。

如果数据库已经提交，但私聊回执发送失败，回复或日志必须准确表达“变更已提交、回执发送失败”，不能重试数据库变更造成重复操作。

## 9. LLM Gateway

### 9.1 目标接口

统一提供：

- `parse_business_intent()`
- `generate_chat_reply()`
- `extract_member_memories()`
- `summarize_member_memory()`
- `summarize_private_conversation()`
- `update_relationship_state()`
- `describe_image()`

建议文件：

- `plugins/llm_gateway/gateway.py`
- `plugins/llm_gateway/contracts.py`
- `plugins/llm_gateway/errors.py`
- `plugins/llm_gateway/transport.py`
- `plugins/llm_gateway/usage.py`
- `plugins/llm_gateway/runtime.py`

领域 Prompt 仍由业务、聊天、记忆和视觉模块分别拥有。Gateway 只统一连接、模型选择、错误处理、JSON 契约、重试、并发和观测，不把所有领域逻辑塞进一个文件。

### 9.2 连接与并发

- 复用共享 `httpx.AsyncClient`；
- 应用启动时初始化，关闭时显式关闭；
- 建议并发容量：业务 2、前台聊天 3、视觉 3、后台记忆 2、HTTP 总量 8；
- 同一会话上层串行，不同会话允许受控并发；
- 取消必须向下传播，不吞掉 `CancelledError`。

### 9.3 错误与重试

统一错误分类至少包括：

- 配置错误；
- 鉴权错误；
- 超时和连接错误；
- 限流；
- 可重试服务端错误；
- 不可重试客户端错误；
- JSON 或契约解析错误；
- 内容为空或响应被拒绝。

只对连接错误、限流和部分服务端错误执行有上限的指数退避。业务请求不得因不受控重试产生重复操作。

日志不得包含 API Key、完整 Prompt、完整响应、私聊正文或图片原始内容。

### 9.4 用量记录

在 `chat_archive.db` 中增加 `llm_usage_events`，只记录：

- 任务类型；
- 模型；
- 输入与输出 token（供应商返回时）；
- 延迟；
- 状态；
- 重试次数；
- 时间。

无法可靠获得 token 或费用时保持未知，不能伪造估算值。

### 9.5 迁移顺序

第一阶段仅建立最小 Gateway 骨架，供新私聊摘要和关系更新使用。第二阶段按风险由低到高迁移：

1. 图片理解；
2. 成员事实抽取和摘要；
3. 群聊与私聊回复；
4. 业务意图解析。

每个调用方单独迁移、测试和提交，并保留切回旧调用路径的运行时能力。业务意图最后迁移，保持原 Prompt、返回契约和严格解析不变。

## 10. Prompt Builder

建议文件：

- `plugins/chat_prompt/models.py`
- `plugins/chat_prompt/builder.py`
- `plugins/chat_prompt/budget.py`

### 10.1 输入结构

Prompt Builder 接受结构化输入：

- 群聊或私聊模式；
- 当前时间；
- 人设；
- 固定安全边界和场景规则；
- 最近上下文；
- 成员事实摘要；
- 关系状态；
- 未完话题；
- 图片原文或永久描述；
- 当前消息；
- @ 与引用方向；
- 是否明确对萝卜猫说话。

### 10.2 信任层级

拼装优先级：

1. 固定安全、权限和业务隔离规则；
2. 场景规则、消息方向和输出契约；
3. 人设；
4. 最近上下文、事实、关系、话题和图片描述；
5. 当前消息。

人设、记忆、关系状态、历史消息和图片描述都属于不可信上下文数据，不能覆盖安全、权限和业务规则。

业务 Prompt 与聊天 Prompt 使用不同类型和构建入口，不能互相传递自由文本指令。

### 10.3 长度预算

初始预算建议：

- 人设：2,000 字符；
- 最近上下文：20 条、合计 6,000 字符；
- 成员事实：1,200 字符；
- 关系状态：600 字符；
- 未完话题：5 条、合计 400 字符；
- 图片描述：2,000 字符；
- 当前消息：2,000 字符；
- 总上下文：约 12,000 字符。

超过预算时优先移除最旧上下文，其次压缩低优先级数据。固定安全规则、消息方向和当前消息不能被裁掉。

上下文格式必须显式包含发送者、QQ、昵称、@ 目标和引用作者，避免把群友之间的对话误认为发给萝卜猫。

## 11. 运行时开关

新增能力分别受以下逻辑开关控制，实际配置名在实施时遵循现有 feature control 命名风格：

- `PRIVATE_MEMORY_ENABLED`
- `RELATIONSHIP_STATE_ENABLED`
- `MEMORY_GOVERNANCE_ENABLED`
- `LLM_GATEWAY_ENABLED`
- `PROMPT_BUILDER_ENABLED`

开关要求：

- 默认安全关闭；
- 可独立关闭；
- 不复制现有私聊用户和群聊群白名单；
- 关闭私聊记忆时仍可保留现有进程内私聊行为；
- 关闭关系状态时不读取、不更新也不注入关系数据；
- 关闭 Gateway 或 Prompt Builder 时可切回尚未迁移的旧路径。

## 12. 后台任务与关闭语义

同一私聊用户的写入、摘要和关系更新串行执行，不同用户受控并发。

关闭流程：

1. 停止接收新的后台记忆任务；
2. 已确认的原文事务不依赖队列，已经落库；
3. 给运行中任务有限排空时间；
4. 超时任务安全取消并保留为可恢复状态；
5. 下次启动重新认领过期租约任务；
6. 旧任务提交仍必须通过版本和水位检查。

因此服务关闭不会丢失已经确认提交的原文状态，未完成的摘要和关系任务可以恢复或重新计算。

## 13. 迁移方案

- 迁移前使用现有备份机制，并明确备份 `chat_archive.db`；
- 备份后执行 SQLite `quick_check`，失败则停止迁移和启动；
- 所有 `CREATE TABLE`、索引和兼容字段迁移均幂等；
- 不删除、不重命名已有表；
- 不回溯处理已有约 3 万条群消息或旧私聊；
- 通过启用水位或启用时间确保只消费开启后的消息；
- 迁移完成后再次执行完整性检查和 schema 断言；
- 重复执行迁移的表结构、索引和数据结果必须一致。

数据库迁移本身采用向前兼容策略。代码回滚时保留新增表，旧版本不读取它们；只有数据库损坏时才停服并恢复迁移前备份。

## 14. 分阶段实施

### 第一阶段：持久化与治理

建议拆成四个小提交：

1. 私聊持久化表、保留策略、幂等迁移和备份验证；
2. 关系状态、版本水位和持久化后台任务；
3. `/记忆` 命令、二次确认、软删除和审计；
4. 白名单私聊接入持久化上下文及独立开关。

### 第二阶段：统一调用与提示构建

1. 建立最小 LLM Gateway；
2. 新私聊摘要和关系更新接入 Gateway；
3. 抽取并测试 Prompt Builder；
4. 按图片、成员记忆、聊天、业务意图顺序迁移；
5. 每次迁移独立验证和提交。

### 第三阶段：可选能力

只预留接口，不在前两阶段扩张实现：

- 人设版本、内容哈希、历史快照和回滚；
- `/人设版本`；
- 仅聊天模式的联网搜索；
- `WEB_SEARCH_ENABLED`；
- 模型费用、延迟和错误状态查询。

联网搜索未来也不得参与违规、禁言、状态、减数或其他业务判断。

## 15. 测试与验收

### 15.1 第一阶段

- 重启后白名单私聊上下文恢复；
- 不同私聊用户之间没有上下文串线；
- 非白名单用户不建立任何持久化私聊记忆；
- 500 条与 30 天双重清理边界正确；
- 清理不误删摘要、长期事实、关系或审计；
- 摘要和关系状态包含来源、水位、更新时间和版本；
- 旧后台任务不能覆盖新状态；
- 更新失败保留旧关系状态；
- 关系状态不会进入任何业务判断；
- 治理命令鉴权、输入校验、预览、确认、过期、取消和审计正确；
- 私人记忆不会发布到群聊；
- 数据库失败不能回复成功；
- 重复迁移结果一致；
- 关闭所有新增开关后原行为不变。

### 15.2 第二阶段

- Gateway 的连接复用、超时、错误分类、重试、并发和取消正确；
- 日志和用量记录不包含敏感正文；
- 不同任务使用独立提示和返回契约；
- Prompt Builder 的预算和裁剪顺序可单元测试；
- 人设和上下文数据不能覆盖安全规则；
- 群友之间的消息不会被误判为对萝卜猫说；
- 图片描述和关系状态只作为低权限上下文；
- 业务意图固定回归语料的结果保持不变。

### 15.3 最终验证

每个阶段先运行相关单元测试，最终必须运行：

- 完整测试套件；
- Python 编译检查；
- 数据库迁移首次执行和重复执行验证；
- 新旧 schema 兼容验证；
- SQLite 完整性检查；
- 公开仓库和 Git 历史隐私扫描；
- Git diff whitespace 和运行产物检查。

测试必须包含真实断言，失败时进程返回非零状态。

## 16. 止损与回滚

- 聊天质量异常：关闭 Prompt Builder、关系状态或私聊记忆开关；
- 后台任务异常：关闭摘要或关系更新，原文持久化不受影响；
- 治理命令异常：独立关闭治理插件；
- 单个 LLM 调用迁移异常：切回该调用方的旧路径；
- 数据库迁移不做破坏性降级，代码回滚后保留未使用的新表；
- 数据库完整性异常：停服，从迁移前备份恢复，并保留故障库供诊断。

每次生产发布前记录当前提交、备份位置、开关状态和回滚命令。发布后分别验证业务指令、群聊、白名单私聊、图片和治理命令的最小冒烟路径。

## 17. 必须保持的边界

1. 聊天模型永远不能直接执行群管理操作；
2. 关系状态和私人记忆永远不能影响业务判断或权限；
3. 群聊、私聊和业务数据不能混淆作用域；
4. 模型推测不能自动升级为确定事实；
5. 私人数据不能写入代码、Git、日志或公开测试夹具；
6. 失败不能被回复成成功；
7. 旧任务不能覆盖新状态；
8. 不回溯重算历史数据；
9. 新能力关闭后，现有生产行为必须保持可用。

## 18. 设计完成标准

本设计经用户确认后进入实施计划阶段。实施计划需要给出每个任务的精确文件、先失败测试、最小实现、验证命令、提交边界和生产迁移步骤。设计确认本身不授权直接部署生产。
