# Prompt Builder 说话人归属修复设计

## 背景与根因

生产灰度开启 Prompt Builder 后，模型曾把一名群友的消息归到另一名群友名下。生产数据库核验显示事件 `user_id`、归档 `user_id` 与 `sender_json.user_id` 一致，不存在数据串号、重复消息或昵称碰撞；关闭 Prompt Builder 后同类聊天恢复正常。

根因是 Prompt Builder 将多名群友的消息和成员记忆放在同一个低权限 `user` 内容块中。虽然每条 JSON 含 `sender_qq`，固定规则没有把第一人称、记忆关联和当前回复对象绑定到明确的说话人标识，模型可能按语义邻近关系合并不同成员。

## 目标

- 在群聊 Prompt 中建立请求内确定、可验证的说话人目录。
- 用 QQ号作为身份关联主键，昵称只作展示。
- 明确第一人称、成员记忆、@和引用的归属规则。
- 保留多人上下文、图片、关系状态、回复概率和旧路径行为。
- 保持私聊与群聊记忆硬隔离，不实现跨群或跨场景共享。

## 非目标

- 不修改聊天归档、成员记忆或关系状态数据库。
- 不修改业务意图、违规记录、禁言或权限逻辑。
- 不增加模型调用次数。
- 不承诺语言模型绝对不会发生语义误判。

## 方案

### 说话人目录

Prompt Builder 在每次请求内，根据当前消息、被引用作者、历史消息和成员资料建立确定的说话人目录。每个非空 QQ号映射为紧凑标识 `S1`、`S2` 等；当前发送者额外标记为 `CURRENT`。映射只在本次请求内有效，不写入数据库。

同一 QQ号始终复用同一标识。相同昵称但不同 QQ号必须得到不同标识；同一 QQ号改昵称后仍视为同一成员。缺失 QQ号的数据使用独立的 `UNKNOWN` 标识，不能与任何已知成员合并。

### 上下文格式

群聊历史、当前消息和成员记忆均使用相同的 `speaker_ref`：

```text
<speaker_directory>
S1 | qq=... | nickname=甲
S2 | qq=... | nickname=乙 | current=true
</speaker_directory>

<history_data>
speaker_ref=S1 | text=我喜欢养花
</history_data>

<member_memory_data>
speaker_ref=S1 | facts=喜欢养花
</member_memory_data>
```

当前消息继续保留消息 ID、发送者 QQ、@对象、引用消息和引用作者；同时增加当前 `speaker_ref`。被引用作者只表示引用方向，不能替代当前发送者。

### 固定规则

高权限 system 规则明确：

- 每条消息中的“我、我的、我们”只属于该条消息的 `speaker_ref`。
- 不同 `speaker_ref` 的消息、事实和关系不得合并。
- 昵称不能作为身份关联键；只有相同 QQ号或相同 `speaker_ref` 才能关联。
- 回复对象由当前消息、@和引用方向决定；`CURRENT` 始终是当前消息发送者。
- 无法确认作者时不得猜测，可保守回复或按原规则输出 `SKIP`。

这些规则只约束聊天表达，不影响任何业务判断。

## 预算与裁剪

说话人目录计入现有 12000 字总预算，不提高模型请求上限。裁剪遵循：

1. 始终保留固定安全规则、当前发送者和当前消息。
2. 优先保留被引用作者及其被引用消息。
3. 按现有规则先删除最旧上下文，再裁剪图片、话题、成员事实和关系数据。
4. 删除最后一条引用某说话人的内容后，才允许删除该目录项。
5. 目录、历史和成员记忆不得出现悬空 `speaker_ref`。

为控制开销，目录与消息使用紧凑文本，不复制成员事实正文。

## 兼容与止损

- `PROMPT_BUILDER_ENABLED=false` 时继续使用现有 legacy Prompt，字节级行为不变。
- Gateway 开关与 Prompt Builder 开关仍相互独立。
- 生产部署时保持 Prompt Builder 关闭；更新后先运行固定语料，再仅开启 Prompt Builder 灰度。
- 若再次出现身份误认，立即关闭 `/提示构建`，无需回滚数据库或 Gateway。

## 测试与验收

必须先写失败测试，再实施最小修复。至少覆盖：

1. 甲说“我喜欢花”，乙发当前消息时，甲与乙的标识和第一人称归属明确分离。
2. 乙引用甲的消息时，当前发送者仍是乙，被引用作者为甲。
3. 两个相同昵称、不同 QQ号得到不同标识。
4. 同一 QQ号使用不同昵称仍复用同一标识。
5. 成员事实只挂在完全相同 QQ号的 `speaker_ref` 下。
6. @第三人不等于对萝卜猫说，现有 `addressed` 语义不变。
7. 缺失作者不能与当前发送者合并。
8. 转义膨胀和总预算裁剪后无悬空标识，当前消息始终保留。
9. 私聊 Prompt 不读取其他用户或群聊数据。
10. Prompt Builder 关闭时 legacy Prompt 完全不变。

验收以 Prompt 内容的结构断言为主，不以模型随机输出作为唯一依据。完成后运行 Prompt Builder、群聊路由、私聊、Gateway、插件加载及全仓测试，并执行公开仓库扫描。
