# 实时群友记忆设计

## 目标

将成员记忆提取与随机接话彻底解耦。目标群内符合归档条件的普通消息持续参与记忆分析，随机回复仍独立使用 `RANDOM_CHAT_PROBABILITY=0.01`，两者互不改变触发概率。

## 方案

按“群号 + 成员 QQ”维护轻量内存批次。成员累计 5 条新消息，或该批次首条消息进入后满 60 秒，任一条件满足即触发一次异步记忆分析。分析上下文从聊天归档数据库读取，而不是依赖随机回复流程。

记忆处理由独立 matcher 承担，优先级不改变现有归档、违规记录和随机聊天 matcher 的行为。处理过程中不发送群消息，也不设置 `block=True`。

## 数据流

1. 聊天归档模块先保存群消息和发送者身份。
2. 记忆 matcher 接收目标群普通成员消息，并更新该成员的批次计数。
3. 达到 5 条时立即调度分析；未达到时由 60 秒计时任务调度。
4. 分析任务从 SQLite 读取该成员近期消息及必要的群聊上下文，调用现有保守提取器。
5. 现有 `apply_candidates` 校验证据消息、说话者、原文引用、敏感词和长度后，写入 `member_memories`，并刷新 `data/member_memory/<群号>/<QQ号>.json`。
6. 随机聊天 matcher 继续独立执行 1% 概率判断，不再负责触发记忆更新。

## 并发与失败处理

- 每个成员同一时间最多运行一个分析任务；分析期间到达的新消息进入下一批。
- 5 条阈值与 60 秒计时只允许一个路径取得当前批次，避免重复分析。
- AI、数据库或文件写入失败只记录警告，不影响群消息处理和随机回复。
- 失败批次不循环重试；后续新消息会形成新批次，并可从归档中带入近期上下文。
- 服务重启会丢失尚未触发的内存计数，但已归档消息和已写入记忆不会丢失。

## 范围限制

- 仅处理已配置的目标群。
- 忽略机器人自身消息、命令式消息和无有效文本的消息。
- 不新增外部依赖，不增加管理界面，不把运行时成员档案提交到 Git。
- 保留现有保守提取规则，不扩大敏感信息收集范围。

## 验证

- 回归测试证明 `should_reply()` 返回 false 时仍会进入记忆批处理。
- 测试 5 条阈值立即触发、60 秒触发、同成员不重复触发、不同成员批次隔离。
- 测试记忆分析不发送消息、不改变随机回复概率。
- 运行现有完整测试集，并在部署后确认 NoneBot、NapCat 和 OneBot 连接正常。
