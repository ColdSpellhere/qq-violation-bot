# 群聊图片理解与视觉记忆设计

## 目标

为萝卜猫增加群聊图片理解能力。插件上线后，只处理聊天功能已开放群中新收到的图片，不回溯或补分析历史聊天图片。所有新图片都会独立于回复概率完成识别并保存文字理解；纯图片消息可以按现有群聊概率回复，明确艾特机器人查看图片时必须基于原图回复。

接入使用现有 `AI_API_KEY` 和 `AI_BASE_URL`，视觉模型单独配置为 `deepseek-v4-flash-vision-exp`。该模型已经通过生产账号的 `/v1/models` 列表确认可用，并以 OpenAI 兼容 `image_url` 内容块完成真实 JPEG 请求。现有纯文字聊天模型不因本功能而更换。

## 功能边界

图片处理必须同时满足以下条件：

- 聊天总开关开启；
- 群聊子开关开启；
- 当前群在群聊白名单中；
- 消息由真人账号发送，不是机器人自身消息；
- 消息事件发生在本功能部署之后。

插件不扫描 `chat_messages` 中的旧记录，也不在首次启动时建立历史图片任务。启动恢复只处理视觉插件自身表中已经存在的 `pending` 或可重试任务，因此不会把上线前的聊天图片加入处理范围。

私聊图片不在本次范围内。违规记录、证据引用、业务查询结果和机器人发送的表情包也不进入群聊图片理解流程。

## 架构

新增独立的 `plugins/chat_vision` 插件，职责分为四个小单元：

1. 图片事件提取：从允许群的实时 OneBot 消息中提取所有 `image` 段及其 URL，按消息 ID 和图片顺序生成稳定标识。
2. 聊天图片存储：安全下载图片到独立目录，记录状态、路径、格式、大小、摘要和过期时间。
3. 视觉调用：把每张图片以 Data URL 形式发送给 `deepseek-v4-flash-vision-exp`，生成可供后续聊天使用的事实性描述。
4. 清理任务：删除超过 7 天的聊天原图，同时永久保留已经生成的文字描述。

聊天归档 matcher 继续先保存原始消息。视觉 matcher 在群消息路由之前处理图片，使当前图片描述在回复生成前可用。每张图片独立处理；一条消息含多张图片时全部进入识别，不设置“只取前几张”的语义截断。

## 数据与文件

聊天原图只写入：

```text
data/chat_vision/images/<group_id>/<date>/<message_id>-<ordinal>.<ext>
```

目录权限为 `0700`，文件权限为 `0600`。文件名只使用校验后的数字标识和受控扩展名，不使用群成员提供的文件名。

在 `data/chat_archive.db` 新增 `chat_image_assets` 表，至少保存：

- `message_id`、`group_id`、`ordinal` 唯一键；
- 原始图片 URL、MIME 类型、字节数和内容哈希；
- 受控的相对文件路径；
- `pending`、`processing`、`ready`、`failed` 状态；
- 永久文字描述和最后错误类型；
- 创建、更新时间、原图过期时间和实际删除时间。

描述字段在原图清理后不删除。重复收到或重复执行同一消息时，通过唯一键复用已有记录，不重复下载和识别。

## 下载与安全

聊天图片下载器由 `plugins/chat_vision` 自己拥有，不导入违规证据的下载器、存储类或配置。它只接受 HTTP(S)，拒绝解析到回环、私网、链路本地或保留地址的主机，限制响应大小，并通过文件签名确认 JPEG、PNG、GIF 或 WebP。

单张图片默认上限为 10 MiB，超限或格式不支持时标记失败，不写入伪图片。下载和视觉请求使用独立超时。视觉模型采用非思考模式，避免为了群聊图片描述产生不必要延迟。

## 与证据图片的硬隔离

违规证据继续使用现有 `evidence/` 目录、证据数据库和 `EvidenceStore`。聊天视觉功能满足以下不可变边界：

- 不导入或调用 `plugins.violation_record.evidence_capture` 与 `evidence_store`；
- 不读取、迁移、索引或重新识别 `evidence/` 中的文件；
- 不在证据数据库中创建任何视觉记录；
- 清理器只接受 `data/chat_vision/images/` 作为根目录；
- 删除前解析真实路径并验证目标仍位于聊天图片根目录内；
- 拒绝符号链接、目录和越界路径；
- 测试用证据目录哨兵文件必须在清理前后保持不变。

因此，7 天策略只适用于聊天图片原图，证据图片的永久保存和现有查询行为完全不变。

## 视觉描述

每张新图片都会调用视觉模型一次，提示模型输出简洁、事实性的中文描述，包括可见主体、动作、场景、表情和重要文字。模型不得臆测不可见身份或背景事实。识别出的文字作为描述的一部分保存。

识图与回复概率解耦：即使消息未命中回复概率，描述仍会写入数据库。以后读取最近聊天上下文时，描述以类似 `[图片理解：……]` 的文本加入对应发送者和消息，不把它伪装成群成员说出的原话。

最近上下文仍遵循现有范围：最近 30 分钟、最多 20 条消息。范围内每条消息的全部图片描述都会加入；范围外描述继续永久保存，但不会无边界塞入每次提示词。

## 回复行为

群聊路由增加图片候选判断：

- 明确艾特机器人且消息含图片：必须回复；当前消息中的全部可用原图直接附加到视觉模型请求。
- 明确艾特机器人并引用一条图片消息：如果被引用原图仍在 7 天内，直接附加原图；原图已清理时使用永久描述。
- 未艾特的纯图片消息：按现有 `RANDOM_CHAT_PROBABILITY` 决定是否回复。
- 图文混合消息：沿用普通聊天概率；命中后同时使用文字和当前原图。
- 普通文字消息：继续使用现有文字模型，但近期上下文会包含永久图片描述。

图片回复继续使用 `character.md`、成员记忆、对话方向和现有安全规则。视觉模型只替换图片相关回复的模型调用，不获得业务操作能力，也不改变业务路由优先级。

当前消息或引用消息含原图时，图片相关回复可能产生第二次视觉调用：第一次生成永久描述，第二次结合角色设定和上下文生成自然回复。这里优先保证描述可复用、回复自然以及失败边界清晰，不采用一次 JSON 调用同时承担两项职责。

## 清理与恢复

清理任务在插件启动后执行一次，之后每天执行一次。它选择已过期且尚未删除的聊天图片记录，逐个验证路径边界并删除普通文件，成功后写入删除时间。描述、哈希、状态和审计时间保留。

服务重启时恢复视觉插件表中未完成的任务。恢复只针对已经由实时图片事件创建的视觉记录，不读取聊天归档来推导新任务。失败任务采用有限次数重试；达到上限后保持 `failed`，不形成无限重试循环。

## 降级行为

- 下载失败：记录错误类型，聊天归档和其他 matcher 继续运行。
- 识图失败：保留图片到 7 天期限并标记失败；命中回复时可再尝试直接视觉回复。
- 图片回复失败：静默降级，不发送虚构的“已看图”文本。
- 原图过期：仅使用永久描述，不重新从过期 QQ URL 下载。
- 配置缺失或视觉模型不可用：不影响纯文字聊天、成员记忆、业务和证据功能。

日志不得输出 API Key、完整 Data URL、图片二进制或带鉴权参数的完整图片 URL，只记录群号、消息 ID、图片序号、阶段和错误类型。

## 配置

新增配置项：

- `CHAT_VISION_ENABLED`：全局识图开关；生产上线时启用。
- `CHAT_VISION_MODEL=deepseek-v4-flash-vision-exp`：独立视觉模型名。
- `CHAT_VISION_IMAGE_ROOT=data/chat_vision/images`：聊天图片专属根目录。
- `CHAT_VISION_RETENTION_DAYS=7`：原图保留天数。
- `CHAT_VISION_MAX_BYTES=10485760`：单图上限。
- `CHAT_VISION_TIMEOUT=60`：下载与模型请求超时。
- `CHAT_VISION_MAX_RETRIES=3`：未完成识图任务的最大尝试次数。

视觉功能复用 `AI_API_KEY` 与 `AI_BASE_URL`，不新增或复制密钥。

## 验证与上线

自动化测试至少覆盖：

1. 只处理实时、允许群的新图片；不扫描历史归档；
2. 同一消息多图全部建立任务且幂等；
3. 每张图识别后永久描述可进入最近聊天上下文；
4. 纯图片按概率回复，艾特图片和引用图片必答；
5. 当前和未过期引用原图进入 OpenAI 兼容 `image_url` 内容块；
6. 原图过期后改用描述；
7. 文件缺失、超限、伪格式、SSRF、API 失败和重启恢复均安全降级；
8. 7 天清理只删除聊天图片，证据目录哨兵和证据数据库不变；
9. 现有业务、证据、文字聊天、私聊、角色和成员记忆测试继续通过。

部署前备份 Git 版本和 `chat_archive.db`，不需要迁移或复制历史图片。部署后启用配置并重启一次，使用允许群发送一张纯图片和一条艾特图片消息做验收，同时确认 `evidence/` 文件数量和哈希未发生变化。回滚恢复旧 Git 版本和数据库备份；聊天图片目录可保留以便排查，不由回滚命令递归删除。
