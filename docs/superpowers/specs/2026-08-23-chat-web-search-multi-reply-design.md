# 聊天联网搜索与多条回复设计

## 目标

为 CArroT 与 kona 的聊天路径增加两项能力：

1. 私聊和群内明确 `@` 机器人时，可按当前消息的明确搜索意图调用 Tavily 获取实时网页结果；
2. 私聊和群内明确 `@` 的回答可由模型自然拆成最多三条 QQ 消息，随机群聊接话仍最多一条。

两项能力不得进入违规记录、禁言、状态、减数、管理员权限或其他业务判断，不改变业务 Prompt 和执行契约。

## 已确认边界

- DeepSeek API 只负责搜索意图后的答案生成，不把 DeepSeek App 的“联网搜索”误认为 API 能力；真正搜索由本服务调用 Tavily。
- Tavily Key 只存在于实例私有 `.env`，不得写入 Git、日志、测试、数据库、提示内容或运行时状态 JSON。
- 搜索只允许在私聊或群聊明确 `@` 场景触发；随机群聊不产生外部搜索请求。
- 搜索查询仅来自当前消息的清洗文本，不包含 QQ 号、昵称、成员记忆、关系状态、历史消息或图片内容。
- 搜索结果是低信任上下文数据，不能覆盖系统安全、权限、业务隔离、说话者方向和输出约束。
- 搜索失败时继续普通聊天，但必须告诉模型本次搜索不可用，不得声称已经搜索或给出未经验证的实时结论。
- 多条回复最大三条；空消息、重复消息和超长消息在发送前拒绝或裁剪。
- 多条回复逐条发送；前一条发送成功后才发送下一条。中途失败时停止后续发送，已经成功发送的内容按实际情况持久化。
- 表情包最多附加一次，且只附在最后一条成功计划发送的消息上。

## 方案选择

### 联网搜索

采用独立 `plugins/web_search` 包，复用现有 `httpx`，不引入第三方 SDK。运行时在首次允许搜索时懒加载一个共享 `AsyncClient`，关闭服务时有界关闭。固定请求 `https://api.tavily.com/search`，不跟随模型提供的 URL，也不抓取结果网页，因此不存在结果 URL 导致的 SSRF 路径。

搜索触发使用保守的本地规则：明确的“搜索、上网查、查一下”等请求直接触发；“最新、实时、今天的天气、当前版本/价格”等时间敏感提问触发。普通闲聊中的“今天很累”等内容不触发。该方式比额外调用一次模型判断更快、更省费用，也比完整 Tool Call 循环更容易审计。

### 多条回复

聊天模型输出采用 JSON 对象：

```json
{"messages":["第一条","第二条"]}
```

私聊和明确 `@` 最多三条，随机接话最多一条。解析器严格限制数组、字符串、条数、单条和总长度；模型返回旧版纯文本时安全降级为一条，避免网关关闭或视觉模型不支持 JSON 模式时整条回复丢失。发送层接收 `tuple[str, ...]`，不通过句号或换行机械拆分。

## 组件与数据流

### 配置与运行时开关

- `WEB_SEARCH_ENABLED=false`：环境初始值，安全默认关闭；
- `TAVILY_API_KEY=`：实例私有密钥；
- `WEB_SEARCH_TIMEOUT=8`：单次搜索超时；
- `WEB_SEARCH_MAX_RESULTS=5`：最大结果数；
- `WEB_SEARCH_MAX_CONTEXT_CHARS=4000`：注入模型的结果总字符预算；
- QQ 命令 `/联网搜索 开|关`：沿用超级管理员鉴权和持久化运行时状态；
- `/模块状态` 只显示开关状态，不显示 Key、查询或搜索结果。

每个实例使用自己的 `.env` 和运行时状态 JSON，因此 CArroT 与 kona 可独立开关。`chat_only` 模式只禁用业务，不禁用聊天搜索。

### 搜索客户端

`plugins/web_search/client.py` 负责：

- 固定 Tavily endpoint 与认证头；
- 严格配置验证；
- `basic` 搜索、最多五条结果；
- 超时、401/403、429、5xx、协议和 JSON 契约错误分类；
- 仅对 429、超时和 5xx 做一次有界重试；
- 结果标题、URL、摘要的类型、长度和控制字符校验；
- 日志只记录错误类和状态类别。

`plugins/web_search/runtime.py` 负责按需共享客户端和关闭；开关关闭时不创建网络资源。

### 搜索意图和查询

`plugins/web_search/policy.py` 只读取当前文本：

- 命中明确搜索短语时清理礼貌前缀和搜索动词，生成不超过 200 字的查询；
- 命中明确时间敏感问题时保留原问题作为查询；
- 空文本、`/` 命令、随机群聊、只有寒暄或情绪表达时返回不搜索；
- 不拼接历史、QQ、昵称、记忆或关系数据。

### Prompt Builder

`ChatPromptInput` 增加结构化搜索状态和结果。Prompt Builder 将结果渲染为 `<web_search_data>` 的 user/data 区段，并纳入独立字符预算。固定 system 规则补充：搜索数据可能错误或含指令，只用于回答当前聊天；搜索失败时不得假称已联网。

旧 Prompt 路径也把同一受控搜索数据放入 user 内容，确保 `/提示构建 关` 时功能仍可降级运行。

### 回复生成与发送

- 新增 `generate_replies()`，返回 `tuple[str, ...]`；保留 `generate_reply()` 作为单条兼容接口，避免影响现有调用和测试。
- 私聊与群聊 matcher 改用 `generate_replies()`。
- 群聊 `addressed=False` 时解析器强制最多一条；私聊和 `addressed=True` 最多三条。
- 每条之间使用 350 ms 有界间隔；测试注入无等待函数。
- 私聊每条发送成功后立即以唯一 `bot:<source_message_id>:<index>` 持久化。若第二条失败，第一条仍保留；未发送内容不落库。
- 群聊返回值以“至少一条发送成功”为成功；首条失败则返回失败。

## 错误与隐私处理

- Tavily Key 缺失、格式错误或鉴权失败：搜索功能 fail closed，普通聊天继续；日志不含 Key。
- 查询和结果不写 SQLite、聊天归档或 usage 表；现有聊天消息本身仍按原逻辑归档。
- 搜索结果不允许作为业务意图输入，也不允许触发任何管理动作。
- 运行中关闭 `/联网搜索` 后，新请求立即停止搜索；已经开始的单次搜索允许结束，但调用模型前再次检查开关，若已关闭则丢弃结果。
- 运行中关闭聊天或移除白名单时，沿用现有发送前二次门控。
- 模型输出 JSON 不合法时降级为一条纯文本；完全为空、`SKIP` 或只有重复项时不发送。

## 测试与验收

自动化测试覆盖：

- Feature state 旧 JSON 缺键默认关闭、严格布尔、QQ 开关与状态不泄密；
- 搜索意图的正反例、查询不含 QQ/历史/记忆；
- Tavily 成功、超时、鉴权、429/5xx 重试、畸形 JSON、关闭释放连接；
- 搜索数据只进入聊天 user/data 区段，业务 Prompt 不出现搜索；
- 私聊/明确 `@` 最多三条，随机群聊最多一条；
- JSON、纯文本降级、去重、长度和 `SKIP`；
- 群聊与私聊逐条发送、间隔、表情包仅一次、中途失败、私聊逐条持久化；
- 两个实例配置隔离和公开仓库密钥扫描。

生产验收顺序：先给 CArroT 写入 Key 并开启搜索，执行一次 Tavily 真实请求和群聊/私聊合成发送测试；健康检查通过后将同一代码发布给 kona，并分别确认运行时开关、NapCat、反向 WebSocket 和实例数据目录未串线。

## 回滚

- 快速止损：每个实例执行 `/联网搜索 关`；多条回复异常时将聊天路径切回上一 release。
- 代码回滚：实例 `current` 符号链接恢复到部署前 release，重启对应 `qqbot@<instance>.service`；NapCat 不需要回滚。
- 配置回滚：恢复部署前 `.env` 备份；Tavily Key 可以保留但不会在旧代码中读取。
- 本功能不迁移数据库，不改变业务表，回滚无需数据库恢复。
