# 图片理解的并发、恢复与预算

本补丁仅修改 `plugins/chat_vision`、`plugins/private_chat/vision.py` 和图片专属测试。聊天匹配器接入由整合分支负责；不修改分词、语义、业务记录或记忆表。

## 群聊

- 优先级 2 入口只写入 `chat_image_assets`，不等待下载或模型。每条消息最多接受前 4 张图片，实时未完成队列最多 256 个资产；达到上限时保留已接受任务并记录不含 URL 的日志。
- 每个机器人进程固定 3 个持久工作单元。群聊与私聊共用 3 个图片处理名额；没有按消息无限创建后台任务。无任务或功能关闭时休眠，开启后继续扫描；存储故障被记录，工作单元继续存活。
- `pending → processing → ready / failed`。失败重试按 5、10、20… 秒退避（上限 60 秒），到 `chat_vision_max_retries` 停止；付款限制仍不重试。新增 `next_attempt_at` 一列，保留旧资产和描述。
- 停机/功能关闭会取消并等待正在执行的操作，释放 processing，不消耗失败次数；异常退出后的 processing 在下次唯一实例启动时恢复。重复启动钩子不会重新领取正在处理的任务。已下载且哈希有效的文件直接用于描述重试。
- 仍只处理原配置恢复时间窗口内的图片，拒绝明显未来时间；按当前群聊白名单和图片开关领取，下载完成后和描述入库前再检查。切换聊天模型不改变已经选定的视觉模型/网关路径。
- 下载包含 DNS、连接和正文读取的总超时。DNS 在线程中执行，保留公网解析、连接地址固定、禁止重定向、MIME/文件头与文件路径保护。
- 每个资产下载与描述共用 `2 * chat_vision_timeout` 的总处理期限。取消本地请求不能证明上游没有计费，因此不声称上游调用严格一次。

### 群聊接入

```python
from plugins.chat_vision.service import wait_for_message_assets

assets = await wait_for_message_assets(event.group_id, str(event.message_id), timeout=8.0)
```

聊天读取当前图片上下文前调用此 API。它只等待同群同消息的资产；超时返回当前状态，调用者取消不会取消公共工作单元，最大允许等待 30 秒。无已入队资产立即返回空列表。纯图片提及若仍 pending/failed 或队列已满，调用方应给出简短处理中/失败反馈，避免静默忽略。普通无图片消息无需等待。

`process_image_event` 仅保留为显式内联兼容辅助函数；生产匹配器使用 `enqueue_image_event`，生命周期使用异步 `await start_workers(store)` / `await stop_workers()`。每个归档数据库按一个运行实例设计，不应让两个机器人进程同时针对同一归档库执行启动恢复。

## 私聊

- 每条消息最多 4 张，整个图片步骤只使用一份 `max_bytes` 总预算。每次下载传剩余预算，流读取失败消耗的字节也计入；无剩余预算不再启动下载。
- 领取处理名额、下载、逐图描述共用一个 `timeout` 总期限。到期取消当前操作，保留已完成的描述与尚未描述成功的当前原图；不再开启后续下载。
- 每张图优先用原视觉模型得到描述。描述成功只返回描述，聊天请求不再同时携带该图原始内容；描述失败/空描述/超时，原图作为一次聊天视觉的后备。多图可同时返回部分描述和不同图片的原图，均不落盘。
- 可选 `still_allowed: Callable[[], bool]` 与全局图片开关一起每 50 毫秒检查；关闭会取消在途下载/模型并丢弃本次待交付结果。调用方应传入当前私聊白名单和该消息记忆代次仍有效的谓词。外部取消会继续向上传递，并释放处理名额。

## 清理与验证

原图仍使用原 7 天保留/每日清理配置。过期文件已缺失（包括可信受管根目录已不存在）时，补记 deleted_at 并清空路径，不创建目录；描述保留。根目录不匹配或任一受管路径存在软链接时仍拒绝清理。

124 项图片相关测试通过，使用临时 SQLite、假 HTTP 网络流、假 OneBot 和假模型：覆盖入口不等待、跨消息并发、私聊并发、队列上限、运行重试、重启/关闭、重复启动、功能关闭、等待者取消、未来/过期/越群拒绝、DNS 线程/总超时、流失败预算、缺失文件与路径安全。私聊 matcher 单元测试使用每测试临时目录；模拟记忆行时隔离 DeliveryLedger，真实源行与投递事务由整合测试验证。未发送 QQ 消息、未调用外部 LLM。

## 数据库存取不占用消息事件循环

图片入口、当前消息资产等待、固定工作单元的领取/状态写回/重试读取，以及启动建表与清理查询，均通过独立的 3 线程存储执行器运行。提交任务前领取异步名额；取消等待只取消该调用者，不取消数据库线程，线程完成回调才归还名额并收取异常。因此反复取消不会制造额外并发或无限执行器排队。

当前资产等待的总期限也包含 SQLite 查询时间。到期返回已经读到的状态；零秒参数执行一次最多 50 毫秒的快照读取。取消等待不会取消公共图片工作单元。领取期间发生取消时先取得数据库领取结果，只有实际领取成功的一方释放自己的 claim；失败的并发领取者不会释放另一个工作单元的任务。停止工作单元后等待已提交的存储操作完成。

新增行为回归验证 SQLite 读取线程、慢查询期限、取消后名额占用、成功/失败领取的取消归属，以及存储失败不会把已取消工作单元变回存活循环。`_active_store()` 仅返回已初始化的内存引用，没有数据库操作。
