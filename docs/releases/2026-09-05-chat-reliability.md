# 聊天请求与投递可靠性

群聊和私聊采用 90 秒总期限，覆盖会话排队、图片处理、搜索、模型和发送。单会话最多接纳 4 个任务，实例最多 32 个；过载或到期任务记录原因并结束。网关的请求期限包含 lane/总并发排队及重试，队列另有容量上限。聊天、图片描述及关系更新默认输出上限 1024 tokens，其余记忆任务 4096；业务意图原有请求载荷不加此字段。

群聊在取得会话锁后、每条发送前重新校验功能与群白名单。私聊保留白名单、记忆开关和消息是否已清除的检查。所有模型回复由 text 段构造，只允许受控贴图选择器追加 image 段。

聊天数据库新增 `chat_delivery_parts`，使用实例身份、会话作用域、源消息生成的 SHA-256 幂等键。生成计划最多 3 段、每段 1200 字，发送前保存；同一事件重放复用已保存的计划。私聊仅在持久记忆开启时建立账本。

- `pending`：尚未开始发送，可在原事件重放时继续。
- `sending`：已取得发送权但没有持久结果，进程崩溃后不可自动认定成功或失败。
- `sent`：已取得发送返回，归档失败时记录警告；原事件重放先修复归档，不重复发送这一段。
- `archived`：发送及归档完成，重放直接结束。
- `unknown`：超时、断连、取消等未能确定结果，保留记录，不盲目重发。
- `cancelled`：清除私聊时同事务清空正文和回执并留下幂等标记，阻止旧计划复活。

OneBot 发送与 SQLite 提交不能构成同一事务，因此不承诺严格一次投递。未知结果必须结合对应 QQ 会话核对，不能仅凭异常进行批量重发。日志只记录短幂等键、段号和错误类别。账本的 SQLite 操作在线程执行，不在事件循环等待数据库锁；默认保留 30 天。群消息回执缺失时归档采用稳定的机器人消息键。

联网搜索在构造查询和客户端出网前两次检查凭据形状、邮箱/手机号、内部地址和内部系统标识；这是明确规则的拦截，不能识别所有可能的机密。只发送当前查询，含敏感字段的查询不发送。搜索整体期限默认 8 秒，最多执行 2 个、共接纳 10 个任务；成功结果缓存 5 分钟，最多 128 条。每客户端进程每日最多 200 次 HTTP 请求，重试也计数；重启会重置该计数，它不是服务商账户级账单限额。

旧提示构造及新提示构造异常回退均受字符预算限制，保留当前消息和数据来源边界。私聊事实优先使用较新的条目。解析、发送类型、队列超时、清除竞态、发送后归档失败及搜索拦截由无网络的行为测试覆盖。
